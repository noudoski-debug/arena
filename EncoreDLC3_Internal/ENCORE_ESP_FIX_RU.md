# EncoreDLC3 ESP 10 FPS → internal: изменения и проверка

## Какой исходник использован

Reference: **`EncoreDLC3_ESP_10FPS_source_fix.zip` из main**, а не старый
`EncoreDLC3.zip`. SHA-256 reference-архива:

```text
86ab386576bd55d953d3a9ed0a97e337bd15ed7bd1298bf55995f28385d5b3ec
```

Исходный архив не перезаписан. Internal-код доработан в **`EncoreDLC3_Internal/`**,
с использованием уже существующего в main internal-каркаса. Это не external
`cheat` из ZIP: renderer и игровой код находятся в `libEncore.so`.
Дамп — `dump 1.14.11949.zip`; другие версии не поддерживаются.

## ESP и нагрузка

В reference синхронный `collectSnapshot()` делает внешние чтения памяти на пути
отрисовки. Исправление из ZIP убирает копирование `s_world`, когда sequence не
изменился, но не делает сам сбор snapshot бесплатным.

В internal:

- `PlayerManager.Update` собирает world-space данные в реестр игрового потока;
- локальный `LateUpdate` проецирует все записи одной камерой и публикует кадр;
- renderer получает `shared_ptr<const Frame>`, а не копирует vector/string на
  каждом `eglSwapBuffers`; Unity/IL2CPP API в render-потоке не вызываются;
- строки обновляются раз в секунду, сначала `DisplayName`, при отсутствии — ID;
- `OnDisable` удаляет запись до оригинального callback; уже полученный render
  frame остаётся неизменяемым. Отключение локального avatar очищает весь реестр;
- записи старше 300 мс удаляются игровым потоком. Без новых опубликованных
  кадров ESP гаснет через 300 мс, а не показывает призраков бесконечно;
- HP text/bar рисуются только при доступном здоровье и валидном max health.
  Armor/Ammo backend не добавлен; они по-прежнему `NO BACKEND`.

**Измерений FPS/CPU на устройстве нет.** Эти изменения убирают конкретные лишние
операции, но не являются обещанием 60/120 FPS и не подтверждают устранение всех
причин исходных 10 FPS.

## Обычный Aim

- Удержание отдельного target ID, без перескакивания между двумя близкими
  кандидатами каждый кадр. Цель немедленно теряется при провале фильтров.
- Exponential smoothing по реальному delta time; wrap yaw по короткой дуге,
  ограничение pitch, защита от NaN/Inf. `Smooth=0` действительно snap;
  значение по умолчанию — **45**. Старый профиль может сохранить `0` — поменяй его.
- Aim применяется в callback игрового потока, а не с частотой overlay.
- Не применяется при открытом меню/FreeCam; scope/bind/distance/FOV сохранены.
- Точки кроме `worldCameraRoot` остаются приближениями, не skeletal bones.

## Death Check

Раздельные `Death Check` у обычного Aim и Silent Ray, по умолчанию включены.
Проверяются локальный игрок и кандидат: respawning, kicked, Spectating,
живое здоровье. Спящие кандидаты исключаются независимо от Death Check.
Respawning/kicked/Spectating исключаются даже при выключенном Death Check.

Цепочка здоровья: `playerEventHandler → Vsj.Health → qXK`.
У generic-типа `Vsi<float, ...>` dump сообщает offsets полей `0x0`: записывать
придуманный offset нельзя. Поэтому `qXK` читается через экспортируемые metadata
API IL2CPP у **inflated runtime class**, после проверки типа `float`.

**Важно:** `qXK` — обфусцированное первичное поле Health. Дамп доказывает его
структурное расположение в типе, но не семантику текущего/предыдущего значения.
Это требует сравнения с реальным HP при уроне/лечении/смерти на устройстве.
Host mock проверяет обращения к metadata, а не семантику поля в игре.

При отсутствующих API, неизвестном типе/здоровье или невалидном значении
Death Check **не разрешает наведение**. ESP при неизвестном HP остаётся,
но без HP bar/text. Это намеренный fail-closed, а не «считать неизвестного живым».
В диагностике видно `Local health` и число `Tracked targets without health`.
Не используется эвристика «стоит рядом с lastDeathPosition ⇒ умер» — она
ошибочно исключает живых после возвращения на место смерти.

## Visible Check

Это больше **не On-screen Only**. Используется `Physics.Raycast` от камеры до
выбранной точки, default raycast layers (`-5`), `QueryTriggerInteraction.Ignore`.
Если препятствий нет — точка доступна; при попадании разрешён collider самой
цели/её дочернего Transform. Чужой collider/стена отклоняет кандидата.
Проверка выполняется для конкретной точки, не «хоть какая-то часть тела видна».

Отсутствие physics API отклоняет кандидат, а не подменяется screen check.
Маски игровых слоёв/реальные collider hierarchy нужно проверить на устройстве;
попадания в собственные collider могут давать ложное отклонение. Видимость
означает физический LOS, а не occlusion renderer/material transparency.

## Silent Ray — эксперимент, НЕ подтверждённый Silent Aim

В reference Silent переписывает `lastTickPosition`. В internal эта запись
**полностью удалена**: положение/сетевое положение/углы камеры не изменяются.

Вместо этого добавлен перехват
`PhysicsScene.Internal_Raycast_Injected` и scoped thread-local контекст вокруг
оригинального **локального `FPHitscan.Update`**. Меняется только направление
подходящего ray, origin/range/mask/hit result не подделываются:

- origin находится менее чем в 2 м от камеры;
- исходное направление близко к forward камеры (dot > 0.9);
- дальность > 2 м, цель находится в дальности ray;
- цель прошла отдельные FOV/Scope/Death/Visible Check;
- физические проверки самого Visible Check не перенаправляются;
- контекст автоматически восстанавливается при выходе/исключении, не действует
  в других потоках и между callback.

**Нельзя по dump.cs доказать, что именно выстрел идёт этим путём.** Другие
callback, NonAlloc/SphereCast/projectile/асинхронные пути не покрыты. Даже внутри
FPHitscan.Update могут быть другие подходящие ray queries: классификация
origin/forward является эвристикой, не доказательством shot-only callsite.
Проверка на устройстве и трассировка реального callsite обязательны до
объявления этого рабочим Silent Aim. Серверная регистрация попаданий не проверена.

`Profiles / effect preview` показывает `Silent rays redirected` и готовность
physics/silent hook. Нулевой счётчик во время стрельбы означает отсутствие
перенаправленных подходящих запросов; **ненулевой не доказывает попадание**.
Режим выключен по умолчанию. Это не полная реализация всех видов оружия.

## Профили

Новые ключи: `aim.death`, `silent.death`, `aim.visible`, `silent.*`,
`esp.health`, `esp.healthtext`.
Старые `aim.screen` / `origin.*` не включают новые physics/shot-переключатели.
Остальные совместимые настройки сохраняются. Death Check включён по умолчанию,
если ключей нет; при загрузке частичного профиля отсутствующие ключи сохраняют
текущие значения, как и другие поля схемы.

## Что проверено здесь

```sh
bash EncoreDLC3_Internal/tools/test.sh
```

- 9 Python tests, совпадение **25 RVA и 31 поля** с дампом;
- C++ callback/snapshot/LOS/Death/sticky target/scoped Silent tests;
- mock metadata API: float, неизвестный generic type, неверный тип, NaN/Inf;
- сглаживание при 30/60/120 Hz, snap/wrap, сохранение настроек;
- UI smoke tests portrait/landscape, root launcher guards, loader syntax;
- отдельно выполнены ASan/UBSan для runtime host-tests.

Android NDK в текущем окружении отсутствует: новая ARM64 `.so` здесь не собрана.
Ни инжект, ни работа игровых API на устройстве здесь не проверены.

## Минимальный device checklist

1. Собрать NDK, запустить только на совпадающем build с GLES3; см. README_RU.md.
2. Сначала включить только ESP. Сравнить FPS с выключенным ESP и с одной/многими
   целями; проверить поворот камеры, поворот экрана и выгрузку сцены.
3. Сверить HP с UI при уроне/лечении/смерти. При `unknown` не отключать Death Check
   вслепую — сначала проверить runtime metadata/доступность экспортов.
4. Обычный Aim, Smooth 45: две близкие цели, переход через yaw ±180, смерть,
   респавн, спящий, отключение, меню. Не должно оставаться старого lock.
5. LOS: открытое место, непрозрачная стена, trigger volume, дочерний collider
   цели; менять выбранную точку. Проверить реальные layer masks.
6. Silent — отдельно, на разрешённом тестовом сервере: смотреть счётчик при
   стрельбе и вне её; проверить, что камера/позиция не двигаются, menu/death/LOS
   останавливают редирект. Подтвердить настоящий shot callsite, hit и регистрацию
   сервером. Ненулевого счётчика для этого недостаточно.

Полная реализация **всех** пунктов Encore и доказанный рабочий Silent Aim
**не заявляются**. Матрица оставшихся ограничений — MODULES_RU.md.
